# 系统与交付文档说明

`docs/` 说明系统应当怎样工作、为何这样设计、如何调用和验证，以及最终交付成果。开发安排和协作历史分别在 `../workflow/plan.md`、`../workflow/ai-log.md`。

以下是计划中的文档，在对应工作开展时创建；本清单不表示它们已经存在或完成。

| 文件 | 作用 | 主要内容 | 更新时机 |
| --- | --- | --- | --- |
| requirements.md | 定义系统要做什么 | 原始要求、已确认业务规则、功能编号、验收条件、范围边界 | 需求确认或变更时 |
| design.md | 解释系统如何组织及关键逻辑 | 模块职责、登录权限、问卷生命周期、跳转算法、校验和提交流程 | 架构或关键流程变化时 |
| database.md | 解释 MongoDB 如何建模及为何这样设计 | 集合、字段、文档样例、内嵌/引用理由、索引、约束、后续迁移 | 数据结构或访问方式变化时 |
| api.md | 提供前后端接口约定 | 路径、方法、权限、请求/响应、错误、分页及样例 | 接口设计或行为变化时 |
| test-cases.md | 提供可复现的验证步骤和证据 | 测试编号、关联需求、前置条件、步骤、输入、预期/实际输出、结果 | 测试设计或执行后 |
| report-phase-1.md | 汇总第一阶段交付 | 项目目标、设计理由、跳转与校验、AI 使用总结、测试结果、问题和解决过程 | 阶段交付前整理 |

`design.md` 补足作业要求的系统说明与关键逻辑说明。数据库文档解释设计，实际初始化和校验代码是可执行实现；API 文档描述真实接口，测试文档不能将预期结果写成实际结果。

报告概括结论并链接到详细文档，AI 使用总结链接到过程日志，避免大段重复。根目录 [README.md](../README.md) 已提供安装、配置、启动、测试命令和文档入口；当前实现边界和实际结果见计划及测试记录。
