# 第一阶段需求与业务规则

依据：`../local/Phase 1.pdf` 及第 1 轮架构设计中用户确认的 D1—D7。仅覆盖第一阶段；本文件定义期望行为，不表示功能已经实现或测试通过。

## 1. 范围与约束

- JavaScript 开发；Node.js + Express 服务端，原生 JavaScript + HTML/CSS 页面。
- 本机运行，手动配置 Node.js 与 MongoDB；所有持久业务数据存 MongoDB，不使用关系数据库或现成问卷系统框架。
- 实现注册登录、问卷创建管理、题目与限制、数据驱动跳转、填写提交、统计和明细。
- 前端保持简单，重点是数据库设计、后端逻辑、测试、文档与真实 AI 使用记录。
- 第二阶段须在第一阶段基础上扩展，保留核心结构、旧数据和主要功能。

## 2. 账号与权限（R1）

- 用户包含用户名、密码哈希、注册时间，支持注册与登录；不存明文密码。
- 用户名区分大小写，Alice 和 alice 可以分别注册（B6）。
- 用户名为中英文文字、数字、下划线或连字符，3—32 个 Unicode 码点，不允许空白；密码 8—128 个码点，可含空格，不要求字符种类组合，不自动去除空格（C6）。
- 登录会话通过 Cookie 标识并保存在 MongoDB，登录后固定 24 小时有效，访问不续期；填写页到期后保留页面答案，重新登录原账号后重试（C1、C2）。
- 登录用户可创建问卷、查看自己的问卷列表、管理自己的问卷和查看其统计/答卷。
- 分享链接用于进入填写，不授予管理权限；填写者填写问卷前必须登录。
- 所有管理和数据查询均由后端验证所有权，不能只依赖页面隐藏按钮。

## 3. 问卷与匿名模式（R2、D1）

- 问卷包含标题、说明、匿名模式、重复填写策略和可选截止时间。
- 每份问卷有稳定的可访问分享链接，例如 `/survey/:slug`。
- 作者可设置三种匿名模式：
  - 强制匿名：所有提交均对作者匿名。
  - 允许匿名：填写者选择匿名或实名。
  - 禁止匿名：必须实名提交。
- 匿名答卷仍保留系统内部用户 ID 用于次数限制，但作者可访问的页面与 API 不返回可识别账号的内部身份字段。
- 匿名保护范围是对问卷作者隐藏账号关联，不承诺对运营者匿名，也不保证填写者主动写入文本的个人信息不可见。
- 服务端验证提交的匿名方式符合问卷设置；实名答卷可向作者展示用户名。

## 4. 重复填写与重试（R3、D2）

- 作者设置每账号每问卷仅一次或允许多次，默认仅一次。
- 匿名和实名共享同一个账号提交次数限制，不能通过切换匿名方式绕过。
- 允许多次时，每次主动填写并成功提交形成独立答卷。
- 双击提交和同次提交的网络重试不能重复入库；多人并发填写与同账号并发提交须正确遵守约束。
- 次数针对成功提交；未提交进度不构成答卷。
- 成功提交后不可修改或撤回；需要再次作答时另交一份，并且问卷必须允许多次填写（B1）。

## 5. 管理生命周期（R4、D3、D6）

- 支持创建草稿、编辑、发布、设置截止时间、手动关闭与重新开放。
- 尚无答卷时，题目、选项、校验及跳转规则可修改；收到首份答卷后这些内容冻结。
- 发布后仍可改标题、说明及截止时间；匿名模式和重复填写策略自首次发布起冻结。
- 重新开放保留原答卷，账号提交次数继续累计，且仍须满足截止时间要求。
- 截止时间可不设；以服务端受理提交时的状态和时间决定是否接受。
- 到期或手动关闭后拒绝新受理，即使填写者此前已开始填写；已检查并受理的请求允许完成保存。
- 仅因到期停止接收的问卷，延长截止时间至未来即可恢复；手动关闭不会因延长时间自动恢复，须明确重开。
- 设计与测试需覆盖无答卷编辑和首份提交并发、已打开页面的定义变化、截止与提交并发等边界。
- 题目定义变化后，旧版页面提交被拒绝，提示重新载入最新版填写；标题/说明更新后，旧答卷展示当前版本，不保留标题说明快照（B3、B5）。
- 草稿允许内容不完整，但结构类型及 ID 须合法；发布和首次发布后的题目更新必须通过完整校验（C3）。

## 6. 题目与校验（R5）

| 题型 | 配置与行为 |
| --- | --- |
| 单选 | 配置选项和必答；提交值必须是合法选项 |
| 多选 | 配置选项、必答及最少/最多选择数量；支持恰好 N 个；不能重复选择同一选项 |
| 文本填空 | 配置必答及最短/最长长度 |
| 数字填空 | 配置必答、最小值/最大值、是否整数 |

- 输入不合法时及时提示；服务端必须复核，不能相信客户端已校验。
- 发布前验证配置本身的合法性，包括限制一致、选项和跳转引用有效、条件与题型匹配。
- 文本按 Unicode 码点计数，组合表情可能计多个；纯空白文本视为空（C5、C4）。
- 非必答空答不执行长度、选择数量和数值范围限制；非空时执行限制，数字 0 为有效答案（C4）。空值标准化及输入转换细节见后端设计，不能只依赖浏览器默认转换。
- 数字采用普通数值精度，整数须可精确表示，不要求精确十进制运算；具体类型见数据库设计（B7）。

## 7. 跳转与循环（R6、D4）

- 规则存储在问卷定义中，由作者配置，不能将具体问卷逻辑写死在代码里。
- 单选按选中选项匹配。
- 多选支持：包含任意指定选项、包含全部指定选项、与指定选项集合完全相同。
- 数字支持：等于、不等于、大于、大于等于、小于、小于等于、闭区间。
- 同题规则可排序，使用第一条命中的规则；无命中时按题目顺序进入下一题，末题后进入结束状态。
- 允许向前和向后跳转，也允许直接以结束问卷为目标；结束后须填写者确认提交才生成成功答卷。
- 回跳用于修正答案，每题最终只保存一个答案，不用于重复收集多组信息。
- 允许规则图有环，不以循环或相同作答状态拦截发布/填写；不设置题目访问次数和跳转步数上限，问卷作者负责其逻辑能否结束。
- 每次作答交互只计算当前题的一次跳转，不自动沿图持续执行；用户不操作时不应产生无限运算或请求。
- 允许用户持续循环，不代表程序后台无限执行。提交复核必须使用可终止的验证方法；所需访问记录和有效路径定义在设计中明确。

## 8. 填写过程与保存（R7、D5）

- 逐题填写并按规则跳转，提供按实际作答顺序返回的“上一题”。
- 修改旧题后保留后续答案缓存，再次访问时回填并重新校验；不再属于最终有效路径的题目不提交、不统计。
- 必答校验只针对最终有效路径；跳过或从路径排除的题目即使必答也无需填写。
- 未提交进度仅在当前页面内保留，刷新或关闭后重新填写；第一阶段不提供服务端进度保存或续填。
- 每次成功提交都保存完整的有效答卷。服务端复核权限、状态、限制、答案和路径，拒绝非法或伪造提交。
- 含回跳时，不能只用最终答案无限遍历规则图来验证；缓存答案、实际交互过程及最终有效路径需要区分。
- 最终有效路径以最终答案从第一题重新计算到结束的结果为准。例：Q1 → Q2 → Q3 回到 Q2，修改后走 Q4 → END，则只保存 Q1、Q2、Q4（B8）。
- 只长期保存最终有效答案及必要路径信息，不长期保存完整回跳/修改历史，不提供作者过程回放（B2）。

## 9. 统计和明细（R8、D7）

- 支持整份问卷统计和单题统计，只统计成功提交的答卷。
- 按答卷而非账号去重统计；同账号多次成功提交分别计数，界面标为答卷数/回答次数，避免误称独立人数。
- 同一答卷内，回跳不会导致同题重复计数，每题只统计最终提交的答案。
- 单选：每个选项的次数、该题有效回答数、选项百分比。
- 多选：每个选项的次数、该题有效回答数、选项百分比。
- 百分比以该题非空有效回答数为分母；空答和跳过不计入分母，多选百分比总和可超过 100%。
- 文本：查看填写内容；数字：查看填写内容及平均值。
- 作者可分页查看逐题填写明细和逐份完整答卷，实名可显示用户名，匿名不暴露账号或内部身份字段。
- 零答卷、零次选项及空数值集合的展示方式在设计与测试中明确，不伪造有效回答或平均值。

## 10. 验收与交付（R9）

- 测试至少覆盖创建问卷、添加题目、跳转、校验、提交和统计；补充权限、匿名、并发重复提交及生命周期边界。
- 每条测试记录前置条件、步骤、输入、预期输出、实际输出和结果；未执行的项目标为待执行。
- 提交可运行代码、MongoDB schema、配置说明、系统/数据库/API/关键逻辑文档、测试用例和阶段报告。
- AI 使用日志按轮次概括实际提示词、输出及修改；由用户决定轮次边界并完成对应 Git 提交。
