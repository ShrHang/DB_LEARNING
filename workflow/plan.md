### 5.4. 实施契约

#### 5.4.1 主代理先完成的共享基础

- 确定 createApp 的依赖入口（db/配置/业务时钟），以及服务错误到 HTTP code 的映射。
- 建立统一 MongoClient、用户仓储和会话装配的边界，避免每个代理各建一套连接。
- 固定配置项、测试库工厂、登录 agent/CSRF helper 和时间控制接口，再交付互不重叠的任务。
- 创建 package 脚本时只引用当前已存在、可执行的代码；未来测试文件不能借空壳或跳过用例制造通过。

#### 5.4.2 数据库初始化

- users、surveys、submissions 的基本 BSON 类型与字段遵循 database.md，建立已有约定的唯一/部分唯一及查询索引。
- surveys 基础校验应允许合法结构的不完整草稿；完整题目/规则的发布校验在 M3 服务层补齐，不将任意业务逻辑塞进数据库 validator。
- sessions 的持久化形状与 TTL 遵循 connect-mongo；不套用业务集合 schemaVersion 要求。
- 直接使用真实数据库验证用户名大小写、索引存在及约束行为；事务探测写入独立测试资源，回滚后不留下业务数据。
- 初始化幂等：重复运行保持既有数据；已有不兼容结构/索引时明确报告，不自动清库或丢弃用户修改。

#### 5.4.3 账号与会话

- API 范围为 /auth/csrf、/auth/register、/auth/login、/auth/me、/auth/logout 及 GET /surveys。
- 密码使用异步 scrypt；在实现前固定并记录盐/派生长度、工作参数、编码格式和比较方式，避免哈希参数隐含于库默认值。验证有空格密码及不同账号随机盐。
- C6 限制与大小写行为保持一致；用户名不小写化、不静默trim密码；响应禁止 passwordHash。
- 将绝对到期时间与 Cookie/存储 expiry 配合，授权以 absoluteExpiresAt 为准；访问、touch 或持久化延迟都不能续期或延长权限。
- 登录后重新生成 session ID 和 CSRF token；登出销毁当前会话；登录失败不建立已认证会话。
- 错误按 API 基线返回；数据库/配置失败不降级到内存保存账号或会话。

#### 5.4.4 列表和页面

- 列表查询的 ownerId 取自真实会话，不接受客户端任意指定其他用户作为查询作用域。
- 测试 helper 直接准备两位作者的合法草稿，验证列表内容、分页及空状态；M2 不实现问卷创建/题目管理端点。
- 页面通过同源 API 和 Cookie 工作；注册后引导登录，成功进入个人列表，登出后不能继续调用受保护 API。
- 公共 API 客户端统一附带 CSRF 与解析错误，页面不重复实现会话规则。填写页专用的缓存/导航恢复留至 M4。

### 5.5. 可委托分工

实际委托按 AGENTS.md 的协作规则执行，不因计划表自动启动子代理。以下是下一轮可采用的分工：

| 承担者 | 候选任务及写入范围 | 并行条件 |
| --- | --- | --- |
| 主代理 | package/锁文件、入口、配置、公共 helpers、会话主流程、文档和集成 | 先完成共享契约，持续推进当前依赖 |
| data_worker | M2-03 的 src/db、初始化脚本、数据库约束测试 | db/配置/测试库接口已固定；不修改主代理入口或系统服务 |
| api_worker（可选） | M2-04 中单独分派的账号输入/哈希/仓储文件 | 精确分配该切片，主代理同步做其他文件；不与主代理同时写 auth service |
| ui_worker | M2-07 的注册/登录/列表文件 | API 形状和公共客户端归属已定，即使后端尚在实现也能独立完成页面工作 |
| verification_worker（可选） | 固定期限/CSRF/列表隔离等补充集成测试 | helpers 已固定，避开实现者已有测试；验证时真实服务可运行 |
| reviewer（可选） | 收尾时核对实现与 C1/C6/权限合同 | 仅审阅，不修改文件，不替代实际测试 |

通常同时选 1—2 项独立任务。任务前列出实际文件清单，每文件唯一修改者；候选目录不等于对全部文件的授权。代理不提交 Git、不更新总日志；主代理记录实际委托与采纳情况。
